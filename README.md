# The Japanese theorem for cyclic polygons in Lean 4

A Lean 4 + Mathlib formalisation of the **Japanese theorem**: for a convex polygon inscribed in a circle, the sum of the inradii of the triangles of a triangulation does not depend on the triangulation. Triangulations are maximal sets of pairwise non-crossing diagonals, with crossing defined geometrically; they are in bijection with a tree model used for the proof. The proof goes through Carnot's theorem (a copy of the Carnot development is in `Japanese/Carnot/`).

**Status:** all statements proved, with no `sorry`. `gate.sh` checks 51 named declarations.

## Main statements

| Lean name | File | Statement |
|---|---|---|
| `Japanese.japanese_quadrilateral` | `Basic.lean` | cyclic quadrilateral: both triangulations give the same inradius sum |
| `Japanese.japanese_polygon` | `Polygon.lean` | n-gon, tree triangulations |
| `Japanese.isTriangulation_iff_exists_tree` | `Combinatorial.lean` | maximal non-crossing diagonal sets ↔ trees |
| `Japanese.geomCrosses_iff` | `Geometric.lean` | for convex position, geometric crossing ⇔ index interleaving |
| `Japanese.japanese_polygon_geometric` | `Geometric.lean` | the theorem for every geometric triangulation |

## Verification

`./gate.sh` builds the library and generates its own `#print axioms` queries for the 51 named
declarations (every Lean name cited in the accompanying paper, plus those queried during
development). The queries are generated by the gate itself, not read from a file in the repository.

The gate fails if any of the following is true:
- a source file contains `sorry`, `admit`, `native_decide`, `axiom`, `#eval`, `run_cmd`, `set_option`, `macro`/`elab`/`syntax`/`notation`, or `import Lean`;
- the build fails;
- a named declaration is missing, or has an extra report;
- a named declaration depends on anything other than `propext`, `Classical.choice` and `Quot.sound`.

Output: `PASS (51 declarations, standard axioms only)`.

`tests/tamper.sh` plants six kinds of fake proof in scratch copies and checks that the gate
rejects each one: a `sorry`; an axiom split across two lines; an `#eval` printing a fake axiom
report; a custom macro; a weakened statement (japanese theorem without convex position: the proof no longer applies.); and a genuine extra
axiom with a long name, so that the report wraps over several lines.

`code/` contains independent numerical checks (Python, exact or high-precision arithmetic) of the
identities and of the hypotheses' necessity. `scratch/` contains the `#print axioms` runs recorded
during development and cited in the paper.

## Build

```sh
curl https://raw.githubusercontent.com/leanprover/elan/master/elan-init.sh -sSf | sh   # if Lean is not installed
lake exe cache get
lake build
./gate.sh
bash tests/tamper.sh
```

Toolchain: Lean `v4.33.1`, Mathlib `v4.33.1` (revision pinned in `lake-manifest.json`).

## Note on how this was produced

The formal proofs, checking scripts and documentation were developed with the help of a
large-language-model AI assistant. The author directed the work, checked the formal statements
against their informal counterparts by hand, and is responsible for the result. The Lean kernel
checks every proof.
